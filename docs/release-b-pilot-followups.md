## Pilot operating boundary (Codex)

David owns alerts, COI review (manual — AI auto-check is off) and reconciliation. Watch the first real customer journeys: worker failures, payment uncertainty, parked deliveries, Stripe-vs-application mismatches. **Stop expansion and investigate** on an unauthorized charge, an incorrect refund/allocation, confirmed data exposure, an unresolved payment outcome, or sustained worker failure. Use the containment procedure when warranted; never reset production or delete records to make an audit count look clean.

## For the next incompatible migration (process lessons from this cutover)

1. Take a content snapshot **before the first paste**, not after it.
2. Run the **complete** SQL gate at the actual execution point; repeat it after any delay or intervening activity.
3. Capture every paste's result row verbatim before loading the next one.

## Brand product list required before first booking, with ordering details (David, 2026-10-07)
Already exists: brand Products tab (name, size, SKU per item), booking page lists the brand's items as checkboxes and saves the picked ones on the booking (`product_skus`), the retailer admin shows them on the booking, and the confirmation and reminder emails include a "what they're demoing" box. Gap: the list is optional (a brand with no items books with none, and the store has nothing to order from) and it lacks the fields a buyer actually orders by. Proposal: (1) require at least one item before the first booking (prompt in the booking flow, pre-filled from the profile, saved back to it); (2) add per-item fields: UPC, distributor (UNFI/KeHE/direct/other), distributor item number, case pack; (3) the confirmation and one-week reminder show these so the buyer can place the order; (4) show in the retailer admin booking detail. Small round; needs a handoff for Codex (data shape change on brands.products and bookings.product_skus, validation, no PII).
